# 1. Memory 记忆管理

## 是什么

Memory 是 Claude Code 的**跨会话持久化记忆系统**。它把用户偏好、项目背景等信息保存在硬盘文件中，下次开新会话时 Claude 会自动加载这些记忆。

**核心区别：**

| 特性 | Memory（记忆） | Context（上下文） |
|------|---------------|-------------------|
| 生命周期 | 跨会话持久化 | 仅当前会话 |
| 存储位置 | `~/.claude/projects/<项目路径>/memory/` | 内存中 |
| 会话结束后 | 保留 | 消失 |
| 用途 | 记住"我是谁""项目是干嘛的" | 当前对话的临时信息 |

## Memory 的四种类型

### ① user（用户信息）
记录用户的角色、技能水平、偏好。比如：
```markdown
# 示例：告诉 Claude 你是 PyTorch 初学者
---
name: pytorch-beginner
description: 用户正在学习 PyTorch，需要教学式的解释
metadata:
  type: user
---

用户是 PyTorch 初学者，正在通过写代码学习。
解释概念时尽量用类比，给出可运行的代码示例。
```

**实际效果：** 保存后，每次你问 PyTorch 问题，Claude 会用教学口吻回答，而不是默认的高级工程师口吻。

### ② feedback（反馈/偏好）
记录你希望 Claude 遵循的工作方式——该做什么、不该做什么。
```markdown
# 示例：你不想让 Claude 在每次回答后做总结
---
name: no-summaries
description: 回复中不要带"总结"段落
metadata:
  type: feedback
---

不要在每次回复末尾写"总结：我做了什么，接下来做什么"。
**Why:** 用户可以直接看 diff，不需要重复描述。
**How to apply:** 所有回复末尾省略总结性文字。
```

### ③ project（项目信息）
记录项目的背景、目标、截止日期等。
```markdown
# 示例：记录项目状态
---
name: learning-roadmap
description: 当前学习路线：从 PyTorch 基础到 Transformer
metadata:
  type: project
---

学习路线：PyTorch 张量操作 → 自动求导 → 线性回归 → NLP → Transformer。
**Why:** 这是一个自学项目，目标是理解深度学习基础。
**How to apply:** 所有代码示例和解释应该逐步推进，不要跳步骤。
```

### ④ reference（外部资源指针）
记录信息在外部系统的位置。
```markdown
# 示例：记录参考资料的位置
---
name: pytorch-docs
description: PyTorch 官方文档链接
metadata:
  type: reference
---

PyTorch 官方文档：https://pytorch.org/docs/stable/
遇到 API 问题时优先查官方文档而非猜测。
```

## Memory 的文件结构

```
~/.claude/projects/-Users-bowen-Developer-Projects-My-Artificial-Intelligence-notes/
└── memory/
    ├── MEMORY.md              ← 索引文件（只记录指针，不写内容）
    ├── pytorch-beginner.md    ← 具体的记忆文件
    ├── no-summaries.md
    └── learning-roadmap.md
```

**MEMORY.md 长这样：**
```markdown
- [PyTorch 初学者](pytorch-beginner.md) — 用户在学习 PyTorch，需要教学式解释
- [不要写总结](no-summaries.md) — 回复末尾省略总结
- [学习路线](learning-roadmap.md) — PyTorch 基础 → Transformer 路线图
```

## 如何使用

### 让 Claude 记住某事
直接在对话中说：
> "记住，我更喜欢中文回复。"
> "记住，这个项目是给高中生用的，代码注释要详细。"
> "记住，不要用 TypeScript，只用 JavaScript。"

Claude 会自动判断该存为哪种类型的 memory。

### 让 Claude 忘记某事
> "忘掉关于 TypeScript 偏好的那条记忆。"

### 查看当前有哪些记忆
> "我现在有哪些 memory？"

# 2. 上下文（Context）—— 仅当前会话

## 是什么

上下文是你和 Claude 在**当前对话**中的所有交流内容。它只在当前会话有效，关掉窗口就没了。

## 上下文 vs Memory 的实际场景

```
场景：你告诉 Claude "我喜欢用中文回复"

├── 如果没存成 memory：
│   会话 1：你说"用中文" → Claude 用中文 ✅
│   会话 2（新窗口）：Claude 又用英文了 ❌
│
└── 如果存成了 memory：
   会话 1：你说"用中文" → Claude 记住 → 用中文 ✅
   会话 2（新窗口）：Claude 加载记忆 → 自动用中文 ✅
```

## 上下文的限制

上下文有长度限制（token budget）。对话太长时，早期的内容会被压缩。所以：
- **频繁用到的偏好** → 存成 memory
- **本次任务特定的信息** → 留在上下文里即可

# 3. /rewind 功能

## 是什么

`/rewind` 让你**回退对话**到之前的某个状态。当你发现 Claude 走偏了方向、或者你想换一种方式提问时使用。

## 使用方式

```
/rewind          # 回退到上一个检查点
/rewind 3        # 回退 3 步
/rewind 5        # 回退 5 步
```

## 实际例子

```
你：帮我写一个 PyTorch 训练循环
Claude：写了 50 行代码...
你：不对，我要的是最简单的版本，只用 5 行

❌ 让 Claude 改写 → 可能改不干净

✅ /rewind → 回到写代码之前 → 重新说："帮我写一个最简单的 PyTorch 训练循环，不超过 5 行"
```

**适用场景：**
- Claude 理解错了你的意图
- 你改主意了，想换一个方向
- Claude 开始胡编乱造（幻觉），想从头再来

# 4. /diff 功能

## 是什么

`/diff` 显示当前会话中 Claude 对文件做了**哪些修改**。相当于 `git diff`，但不需要 commit。

## 使用方式

```
/diff              # 显示所有未提交的更改
/diff --staged     # 只显示已暂存（git add）的更改
```

## 实际例子

```
Claude 帮你改了 3 个文件 → /diff → 看到：

  - train.py:   +15 行（新增训练循环）
  - model.py:   -3 行（删除了无用参数）
  - config.yaml: +2 行（修改了学习率）

你可以逐文件确认改动是否合理。
```

**和 git diff 的区别：**
- `/diff` 是 Claude Code 内置命令，在对话中直接看
- `git diff` 需要在终端里跑
- 结果一样，但 `/diff` 更方便（不用切窗口）

# 5. Git 推送 & SSH 密钥

## 为什么需要 SSH 密钥

GitHub 不再支持密码方式 push 代码（2021 年起），必须用 SSH 或 token。Claude Code 里操作 git 时，需要提前配好 SSH 密钥。

## 配置步骤

### 第一步：生成 SSH 密钥（如果还没有）
```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
# 一路回车，默认保存在 ~/.ssh/id_ed25519
```

### 第二步：复制公钥
```bash
cat ~/.ssh/id_ed25519.pub
# 复制输出的内容（以 ssh-ed25519 开头）
```

### 第三步：添加到 GitHub
1. 打开 GitHub → Settings → SSH and GPG keys
2. 点 "New SSH key"
3. 粘贴公钥内容
4. 保存

### 第四步：测试连接
```bash
ssh -T git@github.com
# 看到 "Hi xxx! You've successfully authenticated" 就成功了
```

## 公钥 vs 私钥

| | 公钥 (id_ed25519.pub) | 私钥 (id_ed25519) |
|---|---|---|
| 给谁 | 放到 GitHub 上 | 留在自己电脑上 |
| 能不能泄露 | 可以公开 | **绝不能泄露** |
| 作用 | 加密/验证 | 解密/签名 |

> **类比：** 公钥 = 挂锁（公开放在那里），私钥 = 钥匙（只有你有）。任何人都能用挂锁锁上东西，但只有你的钥匙能打开。

# 6. /code-review 代码审查

## 是什么

在代码合并（merge）之前，让 Claude 模拟同行评审（peer review），检查代码质量、潜在 bug、安全问题等。

## 使用方式

```
/code-review           # 审查当前分支的所有改动
/code-review main      # 审查当前分支相对于 main 的改动
```

也可以直接说：
> "帮我在合并之前审查一下这段代码。"

## 审查会检查什么

- **逻辑错误：** 边界条件、空值处理
- **安全问题：** SQL 注入、XSS、密钥泄露
- **性能问题：** 不必要的循环、N+1 查询
- **代码风格：** 命名规范、重复代码

## 实际例子

```
# 场景：你写了一个登录功能，准备合并到 main

你：/code-review main

Claude 审查后：
  ⚠️ models/user.py:45 — 密码用 MD5 哈希，不安全，建议用 bcrypt
  ⚠️ routes/auth.py:23 — 没有限制登录尝试次数，可能被暴力破解
  ✅ 其余代码没有问题

你修复 → 再次 /code-review → 全绿 ✅ → 安全合并
```

# 7. 编写自定义 Skills

## 是什么

Skills 让你把常用的提示词/工作流打包成一个**可调用的命令**，用 `/技能名` 一键触发。本质上就是把一段提示词模板化。
注意写好skills后想要调用新的skills，需要重启claude-code，或者使用命令`\reload-skills`

## 两种 Skill

### ① 项目级 Skill（只在这个项目中生效）

位置：`.claude/skills/<skill-name>/SKILL.md`

```
项目根目录/
├── .claude/
│   └── skills/
│       └── train-model/
│           └── SKILL.md    ← 这个 skill 只在当前项目中可用
```

### ② 全局 Skill（所有项目都能用）

位置：`~/.claude/skills/<skill-name>/SKILL.md`

```
~/.claude/skills/
└── review-chinese/
    └── SKILL.md            ← 这个 skill 在所有项目中都可用
```

## 实际例子：写一个"训练模型"的 Skill

```markdown
# .claude/skills/train-model/SKILL.md
---
name: train-model
description: 帮我写 PyTorch 训练代码
---

你是一个 PyTorch 训练代码生成器。当用户调用此 skill 时：

1. 先询问：模型类型（CNN/RNN/Transformer）、数据集、epoch 数
2. 生成包含以下组件的完整训练脚本：
   - 数据加载（DataLoader）
   - 模型定义
   - 损失函数和优化器
   - 训练循环（train + validation）
   - 模型保存
3. 代码中加上中文注释
4. 最后给出运行命令
```

使用：
```
/train-model
```
Claude 就会按照 SKILL.md 中定义的流程来执行。

## Skill 的实际用途

| 场景 | Skill 名称 | 做什么 |
|------|-----------|--------|
| 代码审查 | `/review-chinese` | 用中文做代码审查 |
| 写测试 | `/add-tests` | 自动为改动生成单元测试 |
| 部署 | `/deploy-staging` | 一键部署到测试环境 |
| 日报 | `/daily-report` | 根据 git log 生成工作日报 |
