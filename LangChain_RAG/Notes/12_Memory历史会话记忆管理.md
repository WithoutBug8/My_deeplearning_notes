# LangChain 的历史会话记忆管理

历史记忆的本质：在下一轮请求前，取回与当前用户、当前会话有关的上下文，再一同交给模型。

## 1. 短期记忆（会话内）

- 使用 `RunnableWithMessageHistory` 给原有链附加历史消息。
- `InMemoryChatMessageHistory` 将消息保存在进程内存中，重启程序后会丢失。
- 用 `session_id` 隔离不同会话；同一会话才能取到同一份历史。

基本流程：`session_id` → 获取历史对象 → 将历史填入 `MessagesPlaceholder` → 调用链后自动写回本轮问答。

```python
conversation_chain.invoke(
    {"input": "继续刚才的话题"},
    config={"configurable": {"session_id": "user_001"}}
)
```

适合：命令行演示、临时聊天、单进程应用。

## 2. 长期记忆（持久化）

将记忆保存到 Redis、SQL/NoSQL 数据库或向量数据库；服务重启后仍可恢复。

- **原始消息**：按会话保存，适合恢复完整聊天记录。
- **摘要记忆**：定期压缩旧对话，减少 Token 消耗。
- **向量记忆**：将历史片段向量化，按语义检索相关内容，适合长对话。

长期记忆不能把所有历史无条件塞进提示词：会超出上下文窗口、增加成本，也可能带入无关信息。常见做法是“最近 N 轮 + 历史摘要 + 相关记忆检索”。

## 3. 注意点

- `session_id` 应由服务端生成并校验，避免串话或越权读取。
- 记忆应区分“聊天记录”和“用户偏好/事实”；后者需要可更新、可删除。
- 涉及隐私的信息要脱敏、设置保留期限，并支持删除。
- LangChain 的 Memory 接口迭代较快，优先理解“存储、检索、注入上下文”这三个步骤，不要依赖过时类名。
