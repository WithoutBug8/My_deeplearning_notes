# RAG 中的向量和余弦相似度

向量是文本的数字身份证：把一段文字的语义信息转换成一串固定长度的数字列表，让计算机能够理解文本含义，并进一步做相似度计算。

## 1. 向量 Embedding

1. text-embedding：通过深度学习模型，把文本中的语义特征转换为固定长度的数字序列。
2. 在 RAG 中，文档片段和用户问题都会先被转换成向量，然后再进行相似度匹配。
3. 向量维度越多，通常可以记录更丰富的语义特征，匹配效果可能更好；但维度越高，存储、计算和检索的成本也会更高。
4. 同一个知识库中，文档和问题一般要使用同一个 embedding 模型，否则向量空间不一致，相似度结果会不可靠。

## 2. 余弦相似度

余弦相似度是衡量两个向量方向相似程度的核心算法。它关心的是方向是否接近，而不是向量本身的长度。

公式：

```text
cosine_similarity(A, B) = (A · B) / (||A|| * ||B||)
```

- `A · B` 表示两个向量的点积。
- `||A||` 和 `||B||` 表示向量的长度。
- 结果越接近 `1`，说明两个文本语义越相似；越接近 `0`，说明关联较弱；如果接近 `-1`，说明方向相反。

## 3. 在 RAG 中的作用

RAG 检索阶段的基本流程：

1. 把文档切分成多个 chunk。
2. 将每个 chunk 转成向量并存入向量数据库。
3. 用户提问时，也把问题转成向量。
4. 用余弦相似度等算法找出最相似的若干个 chunk。
5. 把这些 chunk 作为上下文交给大模型生成回答。

简单理解：embedding 负责把文本变成可计算的向量，余弦相似度负责判断“哪几段文本在语义上最接近”。

## 4. RAG中的一些补充知识

RAG主要分为两条线
1. 离线处理
   - 将私有知识库(向量存储)源源不断地添加私有知识文档
     - 向知识库添加来自未来的知识文档
     - 向模型添加私有知识文档
     - 给出模型参考资料，避免模型幻觉
2. 在线处理
   - 用户提问会先于私有知识库作检索获取参考资料，同步组装成新的提示词，询问大模型获取结果
