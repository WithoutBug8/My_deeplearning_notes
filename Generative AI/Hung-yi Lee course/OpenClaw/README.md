# 这是关于OpenClaw运作原理的简介

课程来源于`台湾大学-李宏毅`教授的课程
- 课程链接 [解剖小龍蝦 — 以 OpenClaw 為例介紹 AI Agent 的運作原理](https://www.youtube.com/watch?v=2rcJdFuNbZQ)
---

## 1. AI Agent 的本质
*   **非人工智能本身：** AI Agent（如 OpenClaw）本身并不是人工智能或语言模型，而是一个运行在电脑上、处于人类与语言模型之间的**界面或框架**,。
*   **“动手”能力：** 与一般只提供建议的语言模型不同，Agent 可以自主运行并执行具体任务,。
*   **代表案例：** 教授展示了名为“小金”的 Agent，它能自主创建 YouTube 频道、绘图、搜集资料、配音并上传视频，人类仅负责审核,。
---

## 2. 身份设定与系统提示词 (System Prompt)
*   **身份档案：** Agent 通过读取地端的 Markdown 文字档（如 `soul.md`）来了解自己的名字、主人及人生目标,,。
*   **运作机制：** 每次对话时，Agent 会将这些身份信息、行为准则、工具说明等整合成一段极长的 **System Prompt**，连同用户指令一起发给 LLM,,。
*   **成本开支：** 由于 System Prompt 非常长（可能超过 4000 tokens），每次调用都比较昂贵。
---

## 3. 工具使用 (Tool Use) 机制
*   **核心逻辑：** 语言模型无法直接操作电脑，但它可以输出特定的**工具使用符号**（如 `use_tool`）。
*   **执行流程：** 
    1. Agent 识别到 LLM 返回的特殊工具指令,。
    2. Agent 在本地执行对应的代码（如读取文件 `Read`、搜索网页或执行脚本 `execute`）,,。
    3. Agent 将执行结果回传给 LLM，LLM 再根据结果决定下一步动作,。
*   **自主创收：** Agent 还可以根据需求自主编写并执行“免洗”的小工具脚本,。
---

## 4. 记忆管理 (Memory)
*   **短期记忆（对话历史）：** 由于 LLM 本身没有记忆（State-less），Agent 必须将过去的对话记录不断累加并传回给模型,。
*   **长期记忆与 RAG：** 
    * Agent 会将重要信息写入 `.md` 文件或日记中。
    * 需要时通过 **RAG (检索增强生成)** 技术，利用字面比对和语义比对（Embedding）从记忆库中检索相关片段,。
*   **上下文压缩 (Context Compression)：** 当对话过长超出 Context Window 限制时，Agent 会调用 LLM 对旧对话进行摘要（Summary）以节省空间,。
---

## 5. 进阶协作机制
*   **子智能体 (Sub-agent/Spawn)：** 主 Agent 可以“繁殖”出子 Agent 来处理特定子任务，从而节省主 Agent 的上下文空间，让其专注于高层级规划,。
*   **技能 (Skill)：** 技能是工作的 SOP（标准作业程序）。Agent 可以按需读取这些文档来学习如何完成复杂任务，并能与其他 Agent 交换技能,,,。
*   **心跳机制 (Heartbeat)：** 即使没有人类指令，Agent 也会每隔固定时间（如 15-30 分钟）自动“戳”一下模型，检查任务进度或朝着目标前进,。
*   **定时任务 (Cronjob)：** 允许 Agent 设定在特定时间执行任务，或学会在外部流程完成前进行“等待”,,。
---

## 6. 安全与防御
*   **潜在风险：** 恶意指令可能通过网页内容或评论注入（Prompt Injection），诱导 Agent 执行危险指令（如 `rm -rf`）,。
*   **防御手段：** 
    * **人工审核：** 开启配置，要求在执行指令前必须由人类手动批准（Approve）。
    * **物理隔离：** 建议将 Agent 安装在独立的、格式化后的电脑上，并使用独立的账号，不赋予主账号权限,。
*   **总结：** AI Agent 像是一个在学习中的实习生，需要通过安全的环境（Sandboxing）来允许其尝试与犯错，从而不断成长。
