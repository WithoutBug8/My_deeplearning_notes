# Claude Code 使用笔记

## 1. 基本介绍

Claude Code 是运行在终端中的 AI 编程助手，可以帮助开发者：

* 阅读项目代码
* 修改文件
* 运行命令
* 分析报错
* 编写和优化代码
* 管理项目上下文

当前使用环境：

* 已在 **WSL2** 和 **macOS** 中安装 Claude Code
* 使用 **CC-Switch**
* 当前调用模型为 **Deepseek V4 Pro**

---

# 2. 常用命令

## 2.1 `/add-dir`

**作用：添加 Claude Code 可以访问的额外目录。**

适合当前项目需要引用其他目录时使用，例如前后端分离项目：

```bash
/add-dir ../backend
/add-dir ../frontend
```

注意：
`/add-dir` 不是切换工作目录，而是让 Claude Code 可以读取更多目录。

如果要进入项目，应该先在终端中执行：

```bash
cd your-project
claude
```

---

## 2.2 `/init`

**作用：初始化项目，并生成 `CLAUDE.md` 文件。**

`CLAUDE.md` 可以理解为项目说明文件，用来记录：

* 项目结构
* 技术栈
* 常用命令
* 开发规范
* 注意事项

示例：

```markdown
## Tech Stack
- Backend: Spring Boot
- Frontend: Vue.js
- Database: PostgreSQL

## Rules
- Controller 只处理请求
- Service 负责业务逻辑
- Mapper 负责数据库操作
```

建议第一次进入项目时先运行：

```bash
/init
```

---

## 2.3 `/clear`

**作用：清除当前对话历史，开始新的上下文。**

适合以下情况：

* 当前任务已经完成
* 想开始一个新功能
* Claude Code 开始混淆上下文
* 不想让旧对话影响新任务

使用：

```bash
/clear
```

---

## 2.4 `/compact`

**作用：压缩当前对话历史，保留重要信息。**

适合长时间开发时使用。
如果对话太长，但任务还没结束，可以用：

```bash
/compact
```

也可以指定保留重点：

```bash
/compact 保留项目结构、已修改文件、当前问题和下一步计划
```

区别：

* `/clear`：清空上下文
* `/compact`：保留摘要，继续当前任务

---

## 2.5 `/memory`

**作用：编辑项目记忆文件。**

常用于维护 `CLAUDE.md`，让 Claude Code 记住项目规则。这个记忆存在于`CLAUDE.md`文件中，请妥善保存

适合写入：

* 技术栈
* 项目结构
* 测试命令
* 数据库规则
* 代码风格
* 不希望 Claude Code 做的事情

示例：

```markdown
## Rules
- 不要随意修改数据库结构
- 优先使用现有代码结构
- 不要在 Controller 中写复杂业务逻辑
```

---

## 2.6 `/status`

**作用：查看当前会话状态。**

可以用来检查：

* 当前模型
* 登录状态
* 项目路径
* 连接状态
* 工具状态

使用：

```bash
/status
```

当 Claude Code 表现异常时，可以先用这个命令检查状态。

---

## 2.7 `/cost`

**作用：查看费用和 token 使用情况。**

适合在大型项目或长时间会话中使用：

```bash
/cost
```

可以帮助判断当前任务消耗了多少 token，避免成本过高。

---

## 2.8 `/config`

**作用：打开配置设置。**

可以配置：

* 模型
* 权限
* 是否允许修改文件
* 是否允许运行命令
* 哪些操作需要确认

使用：

```bash
/config
```

建议对危险操作保持谨慎，例如：

```text
rm -rf
sudo
drop database
truncate table
chmod -R
```

# 3. 实际开发流程

## 3.1 项目初始化

进入项目目录：

```bash
cd your-project
claude
```

初始化项目记忆：

```bash
/init
```

补充项目规则：

```bash
/memory
```

建议在 `CLAUDE.md` 中记录：

```markdown
## Project Overview
项目简介

## Tech Stack
技术栈

## Commands
运行、测试、构建命令

## Rules
开发规范和注意事项
```

---

## 3.2 配置模型和权限

先检查当前状态：

```bash
/status
```

再进入配置：

```bash
/config
```

建议权限策略：

* 允许读取文件
* 修改代码前最好确认
* 运行测试命令前确认
* 安装依赖前确认
* 删除文件必须确认
* 数据库操作必须确认

---

## 3.3 编写代码

推荐不要一开始就让 Claude Code 直接改代码。

更好的方式是：

```text
请先阅读相关文件，分析当前实现，不要修改代码。
```

然后让它给计划：

```text
请列出需要修改哪些文件，以及每个文件要改什么。
```

确认后再让它修改：

```text
可以，按照这个方案修改。
```

这样更容易控制代码质量，也能减少误改。

---

## 3.4 功能完善

基础功能完成后，可以继续让 Claude Code 检查：

* 参数校验
* 异常处理
* 返回格式
* 空指针风险
* 安全问题
* 单元测试
* 代码重复

示例提示：

```text
请检查这个功能是否完整，补充参数校验、异常处理和测试。
```

---

## 3.5 性能分析和优化

功能完成后，可以让 Claude Code 分析性能问题：

```text
请分析这个接口是否有性能问题，先不要修改代码。
```

重点检查：

* 是否有重复查询
* 是否有 N+1 查询
* 是否需要分页
* SQL 是否可以优化
* 是否返回了过多字段
* 是否可以使用缓存

确认优化方案后，再让它修改代码。

# 4. 命令速查表

| 命令         | 作用             | 使用场景       |
| ---------- | -------------- | ---------- |
| `/add-dir` | 添加可访问目录        | 项目依赖其他目录   |
| `/init`    | 生成 `CLAUDE.md` | 第一次进入项目    |
| `/clear`   | 清空上下文          | 开始新任务      |
| `/compact` | 压缩上下文          | 长对话继续开发    |
| `/memory`  | 编辑项目记忆         | 补充项目规则     |
| `/status`  | 查看状态           | 检查模型、路径、连接 |
| `/cost`    | 查看费用和 token    | 控制使用成本     |
| `/config`  | 修改配置           | 设置模型和权限    |

---

# 5. 推荐工作流总结

```text
1. cd 进入项目目录
2. 启动 claude
3. /init 生成 CLAUDE.md
4. /memory 补充项目规则
5. /status 检查状态
6. /config 配置模型和权限
7. 让 Claude Code 先分析问题
8. 让 Claude Code 给出修改计划
9. 确认后再修改代码
10. 运行测试并反馈错误
11. 对话太长时使用 /compact
12. 新任务开始前使用 /clear
13. 用 /cost 查看 token 和费用
```
